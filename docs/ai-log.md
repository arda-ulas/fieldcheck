# Agent review log

One entry per story or block of work done with a coding agent. Four fields each: what was asked,
what the agent produced, what was changed or rejected (and why), and how it was verified. Entries
are written by the reviewer, not the agent, and "accepted as-is after review" is a valid outcome.

## Block 3 — S1–S3 endpoints (2026-09-14)
- **Asked:** DTOs separate from entities, validation with ProblemDetails naming the field, duplicate-tag 409, Critical → OutOfService in one transaction, rowversion concurrency with 409.
- **Produced:** `Contracts/*`, `Validation/NotInFutureAttribute`, `Domain/Rules.cs` (pure rules for unit tests), `SitesController`, `AssetsController`, `InspectionsController`, ProblemDetails + exception handler wiring, `JsonStringEnumConverter`.
- **Changed/rejected:** First version put validation attributes on record *properties* (`[property: Range]`); ASP.NET Core throws at runtime because record validation metadata must sit on the constructor parameters. ## Block 4 — S4 report + S5 OData + health + Scalar (2026-09-14)
- **Asked:** report endpoint calling the stored procedure with parameters; OData endpoint with $top cap and 400 on unsupported options; health check; OpenAPI UI. One targeted doc lookup for OData on .NET 10.
- **Produced:** `ReportsController` using `Database.SqlQuery<OverdueAssetRow>($"EXEC dbo.usp_GetOverdueAssets @SiteId = {siteId}")` (parameterized FormattableString), `OData/InspectionsController` over a flat `InspectionRecord` projection, EDM model in `Program.cs`, `Scalar.AspNetCore`, EF Core health check.
- **Changed/rejected:** (1) The Context7 lookup returned only old Web API OData material, so the OData 9 API was verified by compiling, not docs. (2) OData conventional routing also claimed the REST `InspectionsController` (same name as the entity set) and requests 404'd; fixed with `[ODataIgnored]`, found via `UseODataRouteDebug()`. (3) Timestamps serialized with a local offset (`-04:00`) because SQL `datetime2` has no kind; fixed with a UTC-kind value converter in the DbContext and `ODataOptions.TimeZone = Utc`. (4) `$search` was silently ignored rather than rejected; fixed by restricting `AllowedQueryOptions` explicitly.
- **Verified:** curl: report order and DaysOverdue values match the sqlcmd run from Block 2; OData filter/orderby/top/count 200; $top=500, $expand, $search, $apply, $compute 400; /health Healthy; /scalar/v1 and /openapi/v1.json 200.
